Real HDR output for Vintage Story on Windows. Torches, lava, forges, the sun, lightning and the stars go above paper white instead of clipping at it, while the HUD stays at the brightness you choose. It is an ordinary client mod: no launcher, no injector, no ReShade.

This is not Auto HDR or a filter over the finished image. The mod keeps the game's scene in floating point, stops the final shader from clipping, and uses the game's own emissive channel to decide what is a light source. A torch is bright because the game says it glows, not because it happens to be a light-coloured pixel.

What you get

  • Emissive highlights – torches, lava, forges, the sun and lightning are pushed well above paper white.
  • Stars that are actual points of light against a dark sky.
  • Separate UI brightness – set the HUD, inventory, chat and menus independently of the world.
  • Tasteful gamut expansion – already-vivid colours (fire, lava, sunsets, deep sky) move towards P3. Neutrals, skin and muted surfaces do not move, brightness is preserved, and the GUI is never touched.
  • No more sky banding – fixes three 8-bit bottlenecks that the game's normal 8-bit output hides, including the sky gradient being sampled without filtering.
  • Everything tunes live from chat, and is saved.
  • Fails safe – if anything is unavailable, the game carries on with its normal presentation. You never get a black screen.

Requirements

  • Windows 10 (1709) or later, with Use HDR turned on for the display (Settings > System > Display).
  • An HDR display.
  • A current NVIDIA, AMD or Intel graphics driver. Developed and tested on NVIDIA; reports from AMD and Intel users are very welcome.
  • Vintage Story 1.22.

Client-side only. Works in single player and on any server; the server does not need it. On Linux and macOS the mod loads, says so once in the log, and does nothing.

Install

  1. Turn on Use HDR in Windows display settings.
  2. Put the zip, still zipped, in your Mods folder.
  3. Join a world. HDR starts with the first in-world frame. The main menu stays SDR, because the game does not load mods there.
  4. Type .hdr in chat to confirm it is active.

Tuning

All of these take effect immediately and are saved to ModConfig/vshdr.json.

CommandWhat it doesDefault
.hdrShow status and current settings
.hdr on / .hdr offToggle HDR, or retry after a failureon
.hdr paperwhite <nits>Brightness of the world: a fully lit white block300
.hdr ui <nits>Brightness of the HUD, inventory, chat and menus. 0 = same as paperwhite400
.hdr emissive <x>Boost for glowing things: torches, lava, sun, lightning10
.hdr highlight <x>Boost for non-glowing highlights that were about to clip: snow, water glints, clouds0.75
.hdr stars <x>Boost for the stars4
.hdr gamut <0..1>How far vivid colours are pushed towards P3. 0 = off0.5
.hdr peak <nits>Brightest output. 0 = use what the display reports0
.hdr gamma <g>SDR decoding gamma2.2

Where to start: set paperwhite for the overall brightness of the world, then ui for the HUD, then emissive to taste. If highlights look flat or harsh, your display may be reporting the wrong peak brightness – the activation line in client-main.log shows what it reported – so set .hdr peak to its real figure.

Three further switches exist mainly for comparing before and after: .hdr floatscene, .hdr smoothsky and .hdr dither, each taking 0 or 1.

Troubleshooting

.hdr tells you why when HDR is inactive. The same reason is in client-main.log on a line starting [vshdr].

  • “Windows reports this display as SDR” – turn on Use HDR for the monitor the game is on, then type .hdr on.
  • “wglDXOpenDeviceNV failed” – the game is running on a different GPU from the one driving the display, typical of laptops with two GPUs. Set Vintage Story to the high-performance GPU in Windows graphics settings.
  • “game internals this mod hooks have moved” – a game update changed something the mod relies on. The game runs normally in SDR; check here for an update.

Good to know

  • Windows only.
  • Screenshots are SDR. With ui set below paperwhite they come out brighter than usual.
  • If you switch Windows HDR on or off while playing, type .hdr off then .hdr on.
  • Adaptive vsync is treated as vsync on.
  • Gamut expansion is a stylistic choice: the game's art is made in sRGB, so there is no “true” wide colour to recover. .hdr gamut 0 turns it off.
  • Not compatible with mods that replace the game's final shader outright. Overlays that hook OpenGL's buffer swap will not see frames; ones that hook DXGI will.

How it works

OpenGL on Windows cannot ask for an HDR surface, but Direct3D can, and graphics drivers let OpenGL render straight into a Direct3D texture. The mod keeps the scene and the bloom chain in 16-bit float, patches the game's final shader at load time so it expands highlights instead of clipping them, redirects the game's window framebuffer into a float buffer so the GUI blends exactly as it always did, and presents the result through an scRGB swapchain. Every shader change sits behind a switch that defaults to off, where the shaders compute exactly what the unmodded game does.
