Real HDR for Vintage Story

Torches that glow. Lava that burns. Stars that are points of light.

Native HDR output on Windows, as an ordinary client mod – no launcher, injector or ReShade. This is not Auto HDR or a filter over the finished image: the scene stays in floating point from start to finish, and the game's own emissive channel decides what is a light source. A torch is bright because the game says it glows, not because it is a light-coloured pixel.

What you get

  • Emissive highlights – torches, lava, forges, the sun and lightning go far above paper white.
  • A real night sky – bright stars on a dark sky.
  • Separate UI brightness – the HUD and menus are set independently of the world.
  • Tasteful wide colour – vivid colours move towards P3; neutrals, skin and the GUI do not.
  • No sky banding – fixes three 8-bit bottlenecks the game's normal output hides.
  • Fails safe – if anything is unavailable the game carries on in SDR. Never a black screen.

Requirements

Windows 10 or later with Use HDR switched on · an HDR display · a current NVIDIA, AMD or Intel driver · Vintage Story 1.22

Client-side only; works on any server. Tested on NVIDIA – AMD and Intel reports are very welcome. On Linux and macOS it loads and does nothing.

Install

Turn on Use HDR in Windows, drop the zip in your Mods folder, join a world, and type .hdr to confirm it is active. The main menu stays SDR – the game does not load mods there.

Tuning

Live from chat, and saved. Start with paperwhite, then ui, then emissive.

Command What it sets Default
.hdr paperwhite <nits> Brightness of the world 300
.hdr ui <nits> Brightness of the HUD, inventory, chat and menus 400
.hdr emissive <x> Glowing things: torches, lava, sun, lightning 10
.hdr highlight <x> Other highlights: snow, water glints, clouds 0.75
.hdr stars <x> The stars 4
.hdr gamut <0..1> Wide colour. 0 = off 0.5
.hdr peak <nits> Brightest output. 0 = ask the display 0
.hdr on / .hdr off Toggle, or retry after a failure on

If highlights look flat or harsh, your display may be misreporting its peak brightness – set .hdr peak to the real figure.

If it is not working

.hdr tells you why, and so does the [hdr] line in client-main.log.

  • “display as SDR” – turn on Use HDR for that monitor, then .hdr on.
  • “wglDXOpenDeviceNV failed” – two-GPU laptop: set Vintage Story to the high-performance GPU in Windows graphics settings.
  • “internals have moved” – a game update broke a hook. The game runs normally in SDR; check here for an update.

Good to know

  • Screenshots are SDR, so they cannot show what this looks like – you have to see it on the display.
  • Toggled Windows HDR while playing? Type .hdr off, then .hdr on.
  • Not compatible with mods that replace the game's final shader outright.
